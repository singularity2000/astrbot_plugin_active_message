# 主动会话插件

AstrBot 插件 **主动会话插件**（`astrbot_plugin_active_message`）包含两个功能：

- **智能插话**：仅群聊。机器人不再单纯按概率随机回复，而是结合模型判断、群活跃情况、机器人精力计算分数，超过阈值才参与。
- **主动聊天**：机器人根据睡眠、正常、活跃三档作息状态和随机时间，在指定群聊或私聊中主动发起聊天。

此外，可独立开启 **日程意识**：让机器人知道当前及未来七天的安排，并按日程暂停插件自身的插话或主动聊天；不会创建或接管原生未来任务。

首次安装默认关闭。最上方的 **“启用主动会话插件”是总开关**：关闭后，所有会话的智能插话、主动聊天和日程意识都停止。会话组只覆盖对应的全局功能开关，不能覆盖总开关。建议先选一个测试会话，再开启插件。

## 不知道从哪里设置？

**新手建议从 Pages（本插件的“运行检查台”）开始。** 它把设置按用途分好，也能查看机器人为什么没有说话。Pages 和 AstrBot 普通插件配置页共用同一份设置，选一个地方修改即可。具体日程在 Pages 添加和管理；普通配置页只提供日程开关和会话组的排除选项。

| 我想做什么 | Pages 入口 | 原生配置页入口 |
|---|---|---|
| 只让机器人在指定群或私聊生效 | 会话组 | 会话组：选择生效范围 |
| 让机器人判断是否适合接话 | 智能插话 | 智能插话设置（仅群聊） |
| 让机器人隔一段时间主动找人聊 | 主动聊天 | 主动聊天设置（群聊和私聊） |
| 每天晚上不主动聊天、白天更活跃 | 作息与日程 → 作息管理 | 主动聊天设置 → 睡眠时间段／活跃时间段 |
| 让主动聊天等待慢模型，不被插件提前中止 | 上下文与诊断 → 运行资源与超时 → 主动聊天额外总时限 | 运行资源与超时 → 主动聊天额外总时限（留空） |
| 让机器人知道午休、活动等安排 | 作息与日程 → 日程管理 | 日程管理仅控制开关；具体安排在 Pages 编辑 |
| 看机器人为什么没有说话 | 运行总览／决策回放（默认已有阶段记录） | 运行记录与排查（调整保留范围；详情在 Pages 查看） |

几个常见词：**会话**就是一个群聊或私聊；**SID** 是这个会话的地址；**全局**是通用设置；**跟随全局**表示沿用通用设置；**本组覆盖**表示只给这一组单独设置；**阈值**是触发插话的分数门槛；**冷却**是机器人刚说完话后的等待时间。页面里的 **Agent** 就是 AstrBot 的聊天助手。

> **作息不等于禁言，日程不等于提醒。** 睡眠时段只暂停主动聊天，不阻止智能插话或正常回复。想在某个日期或时段同时暂停两种主动功能，请在日程中勾选对应选项。想要准时提醒，请使用 AstrBot 原生未来任务。

## 重要提醒

1. 使用智能插话前，请先关闭 AstrBot 自带的“主动回复”，否则插件会跳过插话并提醒你。仅使用主动聊天或日程意识时，不需要关闭它。
2. 用于判断的聊天记录、近期群消息等资料会发送给你选择的模型服务。请只使用自己信任的服务或中转站。
3. 主动聊天按普通成员权限运行，不会借用管理员权限；智能插话沿用触发消息发送者的身份。某些工具可能因此无法使用。

## 快速开始

第一次使用，按下面五步完成即可；不确定的参数先保留默认值，后面的详细说明可以用到时再查。

### 1. 先选功能，再检查框架设置

如果要用智能插话，请先在 AstrBot 设置中关闭自带的“主动回复”，避免两套功能冲突。仅使用主动聊天或日程意识时，不需要配置插话判断模型。

### 2. 配置判断模式（仅智能插话需要）

在插件配置的“判断模型”中二选一：

- **LLM（普通聊天模型）**：选择一个已在 AstrBot 中配置好的模型，让它判断“现在是否适合插话”。
- **Jev（专用判断模型）**：填写该服务的 API Key，也就是访问密钥。新手可以保留默认地址 `https://api.typesafe.ai/v1/systemone` 和默认模型 `jev-latest`。若使用中转站，必须确认它兼容 TypeSafe Jev；普通聊天模型的接口不能直接填在这里。

判断模型只给出 0～1 的分数，不负责写最终回复。默认最多等 **30 秒**，其中包含重试时间；遇到临时连接问题或服务繁忙时，默认最多再试 **1 次**。重试次数填 `0` 可关闭重试，密钥或返回格式有误时不会重试。判断没有成功，这一轮就不插话。

LLM 和 Jev 可以同时配置，供不同会话组选择。密钥会发往你填写的服务，请确认地址可信。已经保存的超时数值不会被默认值覆盖。

<details>
<summary>使用 Jev 中转站或本地服务时的地址要求</summary>

填写服务方提供的完整 HTTPS 接口地址。插件不会自动补全地址，也不会自动跳转到其他地址；不要把用户名、密码、问号参数或井号片段加在地址里，密钥只填在 Key 栏。只有 `localhost`、`127.0.0.1` 等本机回环地址允许使用 HTTP。

</details>

### 3. 确认聊天参考资料

“聊天参考资料”决定判断时参考多少历史、补充多少近期群消息。刚上手通常保留默认值即可，**这些设置不会删除原来的聊天记录**：

| 设置 | 默认 | 含义 |
|---|---:|---|
| 判断参考的对话历史条数 | `20` | 参考当前对话最近 20 条已保存消息。`0` 表示先选全部，但仍受文字长度上限限制；20 条不是 20 轮对话。 |
| 补充的近期群消息条数 | `50` | 补充群里最近 50 条已保存消息，供判断和聊天时参考。`0` 表示先选全部已有群记录。 |
| 群消息历史不可用时 | `skip` | 默认跳过本轮并说明原因。改成 `runtime` 会使用插件临时记住的片段，信息可能不完整。 |
| 判断输入长度上限（估算 token） | `12000` | token 是模型计算文字长度的单位。这里估算本次提供的资料有多长，不是实际计费数值。 |
| 判断输入字数上限（字符） | `48000` | 与 token 预算同时生效；超出时先去掉较旧参考记录。 |
| 每条参考资料的字数上限（字符） | `4000` | 单条内容太长时，只保留开头并标明缩减。如果提示词本身仍然太长，会跳过本轮并提示。 |
| 使用已有的图片文字说明 | 开启 | 使用框架已经生成的图片说明，不额外识图，也不影响框架继续使用这些说明。 |

**群聊请先在 AstrBot 设置中开启“群消息历史保存”。** 开启后只会积累此后的消息，不能补回过去未保存的内容。它与“群聊上下文感知”是不同功能，不能只开后者。

插件会自动附上选定的历史和当前消息，不必为了让判断模型看到历史而额外填写 `{conversation_history}`。私聊使用已有的对话记录，不需要开启群消息历史保存。

“全部”只包括 AstrBot 仍保留的内容，已删除、未保存或已经整理成摘要的原文无法恢复。图片有现成文字说明时可以复用；没有说明时只保留“这是一张图片”等标记，不会猜测图片内容，也不会额外调用识图。若想复用群里的图片说明，需要开启 AstrBot 的群聊上下文感知和自动理解图片，并且已有可用说明。

**参考资料的限制不会改写原来的聊天记录。** 真正回复时，机器人仍使用 AstrBot 中这段对话的历史、人格和工具设置。如果在提示词里重复添加同一份历史，也会重复占用文字额度。Jev 只支持文字；服务方自己的长度限制仍然有效，出现“内容过长”时，应减少历史或缩短提示词，不要只顾着调高插件上限。

### 4. 配置会话

- 不添加会话组：对所有支持的会话生效；智能插话只处理群聊，主动聊天支持群聊和私聊。
- 添加一个或多个会话组：只在这些组内填写的会话中生效。
- 推荐填写完整 SID，例如：`平台实例ID:GroupMessage:群号` 或 `平台实例ID:FriendMessage:QQ号`。
- 只填数字群号/QQ 号时，插件会在收到明确平台事件后于后台补全。如果启用了多个平台适配器，请填写完整 SID；同一数字在群聊/私聊间出现歧义时，不会擅自猜测。
- 主动聊天只会安排在插件已经知道的会话中，不会主动翻找通讯录里的陌生人。

### 5. 开启功能

确认配置正确后，先打开最上方“启用主动会话插件”总开关，再开启对应全局功能，或将测试会话组的对应功能设为“开启”。普通插件配置页保存后请确认已重载；使用本插件 Pages 的“保存并生效”无需另行重载。建议先只填写一个测试会话，而不是立刻对所有会话开启。

使用主动聊天时，“主动聊天额外总时限”默认留空，沿用主框架的模型与工具限制。如果该项已经填有 `180` 或其他数字，它仍然生效；需要跟随主框架时，请清空后保存。查看执行阶段不需要开启文字快照。

管理员可在当前会话使用 `/active_status`，查看完整 SID、生效范围、阈值、权重和下次主动尝试时间。将 SID 复制到“会话地址（SID）列表”，每项填一个。

如果日志显示“没有原生对话分支”，意思是还没有可用的对话记录。先在那个群聊或私聊里正常与机器人聊一次，或使用 `/new` 新建对话即可，不需要更换 SID。

## 会话组与继承

一个会话组用名称说明用途，并配置多个 SID。组内会话只是共用设置，**历史、冷却、精力和每日轮次仍按 SID 分开**。

| 配置范围 | 会话组可覆盖的内容 |
|---|---|
| 智能插话 | 阈值、停顿等待、最长合并时间、判断结果有效期、三项权重、活跃／精力参数、发言提示词 |
| 判断模型 | 判断模式、判断提示词和判断补充信息模板；模型服务、接口地址、密钥、超时和重试继续使用全局设置 |
| 主动聊天 | 随机间隔、每日上限、时区、睡眠／活跃时段、倍率、任务说明和提示词列表 |
| 日程意识 | 跟随全局／开启／关闭；共享全局日程、添加本组日程、排除指定全局日程 |
| 共享设置 | 历史条数、资料长度上限、已有图片说明、缺少历史时的处理方式，以及两项主动功能共用的冷却时间 |
| 仅全局 | 总开关、模型连接、运行时记录容量、并发额度、主动聊天额外总时限（可留空）、诊断容量与时限 |

- **留空才是跟随全局。** 允许填 `0` 的项目里，`0` 是实际设置，不表示继承。提示词列表为空也表示继承。
- 本组智能插话、主动聊天和日程意识分别选择 **跟随全局／开启／关闭**，默认跟随全局。
- **跟随全局**：采用全局“启用智能插话”或“启用主动聊天”的对应值。
- **开启**：本组开启该功能，可以覆盖对应的全局功能关闭设置；仍要满足范围、配置校验、框架权限及实际触发条件。
- **关闭**：本组不运行该功能。关闭不删除参数，页面仍可编辑。
- 列表为空是全局范围；添加任何组就进入白名单。空组允许保存，但没有目标并会产生警告。
- **三种选择都受最上方“启用主动会话插件”总开关控制**。总开关关闭后所有会话都停止；也不能越过 AstrBot 插件管理中的停用或卸载。
- 本组睡眠／活跃时段留空仍是继承；填写 **`无`** 才表示本组不设置该类时段。
- 同一个 SID 不能放进多个组；同组多个 SID 不会合并成一个聊天会话。

**例子：**全局阈值 `0.7`、共享冷却 `60` 秒。工作群只把阈值填写为 `0.9`，其他项留空，那么工作群使用 `0.9`，其他组仍使用 `0.7`；以后全局冷却改成 `120` 秒，这个工作群也跟随变成 `120` 秒。Pages 用“本组覆盖”徽标显示来源，并对比全局与实际值；“本组固定 · 当前与全局相同”仍是独立设置，以后不会随全局变化。可以一键恢复跟随全局，或只看本页覆盖项。

判断提示词和判断补充信息模板在 **智能插话 → 顶部选择会话组** 中配置，不在会话组管理卡片里。判断提示词决定“要不要开口”，发言提示词决定“准备开口时如何参与”。会话组卡片支持宽屏两列、窄屏单列，可拖动手柄或使用上移／下移；保存后顺序写入原生配置的会话组列表。

## 智能插话的分数

先把下面三项分别算成 0～1 的分数，再按你设置的权重合成总分。权重越大，通常越重视这一项：

| 评分项目 | 含义 |
|---|---|
| 模型判断 | 模型认为此时参与是否自然、有帮助。 |
| 群活跃情况 | 最近一段时间内其他账号的发言条数，以及最近一条消息距今多久。 |
| 机器人精力 | 近期机器人成功发送的消息越多，精力分越低。 |

默认权重：模型 `0.50`、群活跃 `0.25`、机器人精力 `0.25`，也就是重视程度为 2∶1∶1。权重不必加起来等于 1，插件会自动换算占比。

- 正权重：该项分数越高，最终分越高。
- 负权重：该项反向生效，先使用 `1 - 原始分`，再参与加权。
- `0`：该项不参与。
- 三个权重都为 `0`：智能插话配置无效，暂停插话；不因此关闭配置正确的主动聊天。
- 最终分必须严格大于阈值才触发。

### 权重如何合成

插件会按权重大小计算平均分，负权重的项目先把分数反过来。**不需要手算**，可以在 Pages 的试算面板修改分数和权重，直接查看结果；试算不会调用模型或发送消息。

例如三项分数分别为 `0.8、0.6、1`，使用默认权重，最终分就是 `0.8`，高于默认门槛 `0.7`，可以插话。若把活跃权重改成 `-0.25`，最终分会变成 `0.75`。如果门槛也设为 `0.75`，因为只是相等，仍然不会触发。权重填 `2、1、1` 与 `0.5、0.25、0.25` 的效果相同。

### 活跃分与精力分

**群活跃分**看两件事：最近有多少消息，以及最后一条消息离现在多久。默认统计最近 **10 分钟（600 秒）**，以 **8 条消息**为目标；聊天越多、越近，分数通常越高。若最后一条消息已过去 **5 分钟（300 秒）**，按默认设置，活跃分会降到 0。其他账号发的消息都会计入，不区分它们是真人还是其他机器人。

**机器人精力分**看最近说了多少次话。默认统计最近 **1 小时（3600 秒）**，以 **5 次发送**为目标：发送 0、1、2、3、4、5 次时，分数分别为 `1、0.8、0.6、0.4、0.2、0`。较早的发言超出统计时段后，就不再占用这部分精力；它不是每秒自动恢复一点的体力条。插件能够统计到的普通回复也会影响精力和冷却。

**精力分为 0 不等于禁止插话。** 默认权重下，另外两项都是 1 时，总分仍有 `0.75`，可以超过默认门槛 `0.7`。这些统计按 SID 分开；若 AstrBot 设置成同一个群里每个人都有独立会话，统计也会分别计算。

统计记录同时受时间窗口和“每个会话的短期记录上限（条）”上限约束。该上限不是原生历史读取条数；后者在“聊天参考资料”里独立设置。

### 消息如何合并，判断何时作废

| 设置 | 默认 | 用途 |
|---|---:|---|
| 停顿等待 | 3 秒 | 大家停顿这么久后开始判断，避免每一条都调用模型。 |
| 最长合并时间 | 10 秒 | 从本批第一条消息开始计算；群里一直有人说话，也不会无限延后判断。 |
| 判断结果有效期 | 45 秒 | 从准备好本次判断资料时开始计时，包含排队和调用时间；过期后不再使用这次结果。 |

例如消息在第 0、2、4、6、8 秒连续到达，插件最晚在约第 10 秒结束合并等待，把这批消息一起处理；如果判断名额已满，仍需排队。判断开始后，普通新消息不会反复打断它；真正开口前还会参考最新聊天情况。

如果有人正常 @ 或唤醒机器人、切换了对话、机器人已经说话进入冷却，或这次判断已经过期，旧判断就不会再触发插话。插件停止后也一样。已经向模型发出的请求即使被取消，服务方仍可能计费。

## 自定义提示词和占位符

“判断提示词”和“智能插话发言提示词列表”是两套不同配置：

- 判断提示词：给 LLM/Jev，决定模型判断分。
- 发言提示词：告诉机器人这次该怎样开口。聊天记录、昵称等内容会单独作为参考资料提供，与你填写的行为要求分开。

提示词列表每次随机选择一条，也可能连续选到同一条。主动聊天还可以填写“任务说明”。无论怎样修改提示词，插件发起的主动聊天都只能发送到原来的会话。

占位符就是自动填空，例如 `{mood}` 会换成当前作息状态。**不需要写代码**，保留两侧花括号即可；不要填入代码或计算式。涉及聊天记录等内容时，插件会另外附上参考资料。常用占位符：

| 占位符 | 用途 |
|---|---|
| `{persona_prompt}` | 当前会话的人格文字说明，太长时会缩短；不代表机器人收到的全部要求。原来的人格和工具设置仍然有效。 |
| `{persona_name}` | 当前人格名称。 |
| `{conversation_history}` | 按“聊天参考资料”设置选取的历史文字，过长会缩短，不等于群里的全部发言。 |
| `{current_message}` | 当前触发判断的那条消息，过长会缩短。 |
| `{image_descriptions}` | 已有的图片文字说明；没有说明时不会猜测内容。 |
| `{recent_messages}` | 按设置选取的近期群消息；如果选择了 `runtime`，可能只是临时记住的不完整片段。 |
| `{now}` `{current_time}` `{date}` `{weekday}` `{time}` | 当前时间、日期、星期和消息时间。 |
| `{platform}` `{platform_id}` `{message_type}` `{chat_type}` `{session_id}` `{sid}` | 平台、实例、群/私聊类型、会话编号和完整 SID。 |
| `{group_id}` `{sender_id}` `{sender_name}` `{user_id}` `{username}` | 群号、真实发言者 ID 和昵称；后两个是兼容别名。主动聊天没有原始发言人时为“不适用”。 |
| `{group_message_count}` `{silence_seconds}` | 活跃统计时长内其他账号的消息数、距最近一条消息的秒数。 |
| `{activity_score}` `{energy_score}` | 群活跃原始分、机器人精力原始分。 |
| `{model_score}` `{score}` `{threshold}` `{decision_reason}` | 模型分、最终分、阈值和理由；判断提示词中不要使用判断后才产生的 `{model_score}`、`{score}`、`{decision_reason}`；主动聊天中这些判断分字段为“不适用”。 |
| `{activity_level}` `{mood}` `{trigger_type}` | 群活跃档位（低/中/高）、作息状态（睡眠/正常/活跃）和触发类型（智能插话/主动聊天）。 |
| `{user_last_message_time}` `{user_last_message_time_ago}` `{ai_last_sent_time}` `{unreplied_count}` | 最近真人发言、距今时间、机器人最近发送时间和连续未获回复次数。 |
| `{user_context}` | 根据当前会话信息组成的概况。 |
| `{schedule_current}` | 本会话正在进行的日程；关闭日程或没有事项时为空列表。 |
| `{schedule_upcoming}` | 未来七天内每条日程的下一次安排，最多十二项；不是所有重复轮次的长清单。 |

开启日程意识后，机器人也会自动收到日程资料，不必专门添加占位符。请使用上表或页面提供的占位符；`{calendar_today}` 不受支持。

## 主动聊天作息与调度

- **睡眠**：睡眠时间段内不发起新的主动聊天；只保留下次尝试时间，不会睡醒后补发一批积压消息。
- **正常**：使用配置的最短/最长随机间隔。
- **活跃**：将随机间隔乘以活跃倍率，通常更容易主动聊天。

在“主动聊天设置 → 每个会话每日主动聊天上限（轮）”中设置每天最多主动聊几轮。一轮即使分成多条消息，也只计一次；至少确认一条发送成功才计数，不代表对方已读。

**到了时间只是尝试，不保证一定发言。** 机器人可以判断“不适合打扰”而不发送；如果同时执行的任务已满，或这个会话的聊天助手正忙，也可能晚一些开始。睡眠设置不会阻止正常 @ 和问答。

主动聊天使用 AstrBot 原本的聊天助手，沿用这段对话的历史、人格和工具设置。主动时机由插件安排，不会在主框架的未来任务列表中登记一条任务。当前只支持 AstrBot 内置聊天助手（设置中标为 `local`），暂不支持第三方助手。

时间段可以跨午夜，也可以用英文逗号分隔多个区间，例如 `23:00-07:00,12:00-13:00`。`23:00-07:00` 表示 23:00 开始、07:00 结束；起止相同表示全天。**全局时段留空表示不设置；会话组时段留空表示跟随全局，填写“无”才是不设置本组的这类时段。**

睡眠与活跃时段重叠时，睡眠优先。如果整个等待过程都在活跃时段，默认间隔为 30～180 分钟乘以 0.6，也就是 18～108 分钟；睡眠期间安排的机会可能在睡眠结束时直接尝试。

“每日上限”只限制成功主动发言的轮次，不限制失败或未发送的模型尝试次数。你刚发言不会自动重新计算整段间隔，多次不回复也不会自动延长间隔。“心情”占位符目前只表示睡眠、正常或活跃，不是对机器人情绪的分析。

### 哪些设置不会相互影响

- “发言后等待时间（共享冷却，秒）”同时限制智能插话和主动聊天；正常 @ 回复不受它限制。
- 判断模型只打分；主动聊天不经过插话阈值。聊天内容仍由原生 Agent 产生。
- 如果机器人思考或准备图片期间进入睡眠，或碰上暂停日程，发送前会再检查，放弃尚未交给平台的内容，并说明原因。已经发出的消息不会撤回。用户期间的正常聊天仍由 AstrBot 处理，不会因为用户刚说话就自动取消主动任务。

### 主动聊天要等多久

在 **Pages → 上下文与诊断 → 运行资源与超时**，或原生配置页的 **运行资源与超时** 中，只有一项“主动聊天额外总时限（秒，留空跟随框架）”：

| 填法 | 实际行为 |
|---|---|
| 留空（默认） | 插件不设置整轮截止时间。模型请求、重试、备用模型和工具执行沿用主框架自身的限制；等待较久仍可显示“进行中”。 |
| 正整数，例如 `900` | 在主框架原有的限制之外，再给整轮主动聊天增加 900 秒上限。达到上限时请求中止；不会延长主框架原本更短的模型或工具限制。 |

填写数字后，一轮任务拿到执行名额就开始计时，包含 **等待这个会话空闲 → 准备聊天资料 → 模型思考、重试和使用工具 → 发送及保存聊天记录**。在此之前，因为其他主动任务太多而排队等待执行名额的时间不计入。

留空后，整轮任务可能等待较长时间，不能保证在几分钟内结束。某次模型尝试未成功时，AstrBot 还可能重试或切换备用模型；插件会等它给出最终结果，再判断整轮是否失败。已经发出的内容不会因后续超时被撤回，已确认的成功轮次也不会因此取消。

这项设置与智能插话的 **“判断请求超时（秒）”，默认 30 秒** 无关；后者只限制“要不要插话”的打分请求。

## 日程意识

### 先试一条午休日程

1. 打开 **作息与日程**，顶部选择全局或一个测试会话组。
2. 打开“启用日程意识”，或把“本组日程意识”设为“开启”。插件总开关也需要开启；智能插话、主动聊天可以保持关闭。
3. 点击“添加全局日程”或“添加本组日程”，填写“午休”、开始日期，选择“时段”，填 `12:30` 到 `14:00`。想说明是谁的安排，可以在“日程说明”里写“机器人午休”或“群友午休”。
4. 选择“每周”，勾选周一到周五。想每天生效就选择“每天”。按需要勾选“期间暂停智能插话”和／或“期间暂停主动聊天”。
5. 点击“加入页面草稿”，在“日历预览”中点击日期检查结果，最后点击页面右上角 **保存并生效**。

**预期效果：**午休期间，勾选的插件主动功能暂停；正常 @、命令和框架原生未来任务不受影响。14:00 后恢复原有规则，但不会立刻补发消息。若两个暂停选项都不选，机器人只知道这条安排，不改变发言时机。

### 知道日程，不等于自动提醒

- **日程就是一条安排**：机器人午休、群里聚餐、和某人的约定，都在同一个日程列表里添加。在名称或说明里写清楚是谁的事、要做什么即可。
- **知道安排，不等于已经做完**：写了“机器人今晚看书”，不代表它真的读过一本书。某个群或私聊专用的安排，添加到对应会话组，只提供给这个组里的会话。
- **准时提醒**：直接在聊天里请 Agent 使用 AstrBot 原生未来任务，例如“每天 12:25 提醒我准备午休”。本插件不创建、不接管、不拦截这些提醒，也不判断原生提醒是否打破安静时段。

日程意识可以单独开启：让机器人正常回复时知道安排，但不主动搭话。日程只作为当次回复的参考，不会替换原来的人格或聊天记录。若 AstrBot 版本不支持提供这类临时资料，插件会提醒并跳过，请根据提示升级框架。

### 全局和会话组如何配合

**会话组日历 = 全局日程 + 本组新增 − 本组排除。**全局日程标注“来自全局”，可以在本组排除或恢复继承；修改全局事项请切换到全局范围。排除不影响其他组。多个日程重叠时，只要其中一条要求暂停，该插件功能就暂停。

**不用填写日程编号或组编号。**在 Pages 创建日程时，只需填写名称、说明和时间，再在“日程适用范围”中选择全局或会话组。关联由插件自动维护，修改日程名称或组名不会让已有设置失效。

- **Pages**：选择顶部的会话组后添加本组日程；全局日程可直接点“本组排除”或“恢复继承”。编辑日程时也能按组名调整适用范围。
- **原生配置页**：控制日程意识开关；会话组的“本组不使用的全局日程”仍可按名称选择。列表来自已保存的日程数据，带有时间，同名同时间的安排还会加上序号。具体日程在 Pages 添加、编辑和删除。
- **原生配置页的排除列表来自已保存的数据**：在 Pages 保存全局日程后，重新打开原生配置页更新选择列表。Pages 可以直接操作当前草稿，无需分两次保存。

删除全局日程，或把它改成本组日程时，插件会清理对应的旧排除设置。Pages 删除会话组时会确认并删除其专属日程，不删除全局日程；原生配置页删除组后，留下的专属日程需重新选择适用范围或删除，不会自动变成所有会话可见的全局日程。

### 日程数据保存在哪里

日程记录保存在 AstrBot 分配给插件的数据目录下的 `agenda.json`，与原生配置里的开关、会话组和提示词分开。Pages 仍在同一处编辑和保存，日历按当前草稿预览；关闭日程意识不会清除记录。备份或迁移插件时，请同时保留原生配置文件和整个插件数据目录。

日程只从 `agenda.json` 读取和保存，不读取或迁移原生配置中的日程记录。没有日程数据文件时，从空列表开始，在 Pages 添加即可。一次性日程过期后不会自动删除，可在 Pages 中按需清理；记录仍计入日程数量上限。

如果页面提示内容已在另一处修改，先重新载入，确认最新内容后再编辑，不要拿旧草稿覆盖。如果写入失败、数据文件损坏，或一次尚未完成的保存与其他修改冲突，插件会保护已有数据并暂停运行。遇到这类情况，**先备份设置和 `agenda.json`，不要直接删除文件。** 按日志提示检查保存位置能否写入、是否有冲突，处理后再重载。日程文件在保存中断时还可能包含待保存的设置，请不要把完整文件公开分享。

### 日期和重复方式

| 配置 | 含义 |
|---|---|
| 全天 | 从当天零点持续到次日零点；可以配合各类普通重复方式 |
| 时段 | 按开始／结束时间计算；结束早于开始表示次日结束，相同时间请改选全天 |
| 不重复 | 只在开始日期发生一次 |
| 每天 | 从开始日期起，每天生效 |
| 每周 | 周一至周日可多选，例如周一／三／五，或周六／日 |
| 每年 | 同月同日重复；2 月 29 日只在闰年出现，不擅自改成 2 月 28 日 |
| Cron | 五段表达式决定开始时间，“每次持续分钟”决定结束；只计算日程，不创建发送任务 |

重复截止日期可留空，填写后包含当天开始的轮次；跨午夜事项不会在零点被截断。日期范围为 1900～2199 年。

Cron 顺序为 `分 时 日 月 周`，例如 `0 9 * * mon,wed,fri` 表示每周一／三／五 09:00 开始。星期数字采用周日 `0` 或 `7`、周一 `1` 的约定；日期和星期同时限制时需同时满足。持续时间为 1～1440 分钟。密集规则在某天多次出现时，日历按事项合并展示，详情列出前三次并注明还有更多；实际暂停判断不依赖展示条数。

日程使用“作息与日程”里的时区；留空时先用 AstrBot 为会话设置的时区，再用系统时区。中国大陆用户需要统一按北京时间运行时，可填写 `Asia/Shanghai`。若同组会话的时区不同，页面按第一个会话预览，实际各按自己的时区运行。在有夏令时的地区，普通日程的起止时刻被跳过时会跳过该轮，时刻重复时只采用第一次。

点击日历中的日期可看当天安排，也可以切换月份或点“今天”。日历按当前草稿预览，未保存的修改还没有生效；关闭日程意识后仍能预览，但机器人不会参考它，也不会按日程暂停发言。

全局和每个会话组各最多新增 **100 条日程**，整个列表最多 **1000 条**。提供给机器人的当前安排和近期安排各最多 **12 项**，每项说明最多取前 **160 字**；日程较多时，暂停发言的规则仍会检查所有适用安排，不会因为摘要缩短而漏掉。

后续计划：提供可选的 AI 每日角色日程生成，生成结果可查看和修改；当前版本暂不支持。

## 运行检查台（Pages）

在 AstrBot 管理界面中，找到本插件的页面入口，打开“主动会话 · 运行检查台”（部分界面显示为 `console`）。需要先登录 AstrBot；不要直接打开插件文件夹里的网页文件，那样无法连接正在运行的插件。

| 子页 | 适合做什么 |
|---|---|
| 运行总览 | 查看总开关、会话范围、共享冷却、每日轮次、下一次计划和最近原因 |
| 决策回放 | 选择一次运行，查看它正在做什么、为什么开口或没有开口，以及是否已经发送 |
| 会话组 | 管理名称、SID、共享冷却、功能选择和排序；宽屏两列、窄屏单列 |
| 智能插话 | 调整判断模式、插话分数门槛、权重、停顿等待和精力，以及全局／分组的判断与发言提示词 |
| 主动聊天 | 调整间隔、每日轮次、任务说明和提示词 |
| 作息与日程 | 检查作息时间轴，管理全局／分组日程，在日历预览中查看安排和当前暂停原因 |
| 上下文与诊断 | 设置聊天参考资料、已有图片说明、临时文字快照和同时运行的任务上限 |

不清楚某个设置是什么意思时，查看旁边的 **圆圈问号**。鼠标悬停或点击都能查看；点击可固定说明，再点外部或按 Esc 关闭。手机可以直接点，键盘也可以用 Tab 移到问号上。

在设置页顶部先选“全局设置”或某个会话组。**修改只是草稿，点击“保存并生效”后才生效。** 设置和日程会分别保存；等待中的判断会取消，下次主动时间会重新安排，成功发送次数保留，旧运行记录清空。如果机器人正在执行任务，页面会要求稍后再保存；如果另一处已修改内容，会拒绝覆盖，需要重新载入。

“有未保存修改”旁边会列出 **哪个范围 → 哪个页面 → 哪个设置** 有变化，不显示提示词正文或密钥。列表较长时可以左右滚动。改回原值后，相应提示会消失；切换主题、月份或页面不算修改设置。保存失败时，草稿仍会保留。

页面支持浅色、深色和自动主题；自动模式会跟随 AstrBot，无法取得主题时跟随系统。电脑和手机都可以使用。页面会按登录用户记住主题、常用页面和教程状态，这些偏好不会改变机器人的发言计划。

左侧的 **新手引导** 可随时重新开始，支持下一步与跳过；只介绍操作，不会改配置或发送消息。设置页顶部的编辑范围随滚动保持可见，避免把本组设置误当全局。

点击提示词输入框，底部会出现 **占位符助手**，只列出这个输入框能用的占位符。可以搜索，点击就插入光标处；选中了一段文字时会替换那一段。点击其他区域或按 Esc 可收起。也可以查看 **占位符大全**。插入后仍需保存；如果自动复制不成功，可以从弹窗手动复制。

### 文字快照与隐私

**默认就能查看执行阶段，不必开启文字快照。** 可以看到当前在做什么、等了多久、判断分数和发送结果。“临时记录请求文字快照”默认关闭，只有需要检查发给模型的文字、模型回答或工具结果时才开启；开启前的内容不会补录。

- 记录是临时的，不会长期保存。步骤历史默认最多 **50 次运行、10 MiB**，已结束记录默认保留 **30 分钟**，每轮最多记录 **100 个步骤**；超出部分会清理或注明省略。主动任务还没结束时，仍可查看当前阶段和耗时，即使之前的步骤已经清理。点击“刷新记录”可更新；重载、保存设置或清空记录会移除旧步骤，但清空记录不会停止任务。
- 能登录 AstrBot 管理界面并管理插件的人，可能看到这些资料。如果多人共用管理界面，开启文字快照前请先考虑聊天隐私。
- 页面会隐藏已设置的密钥，文字记录也会隐藏已知密钥，但聊天内容和工具结果仍可能包含隐私。**分享截图或日志前，请自行检查。**
- 每一步的文字默认最多 **16000 字符**，超长时会标明缩短。图片、音频等不会保存成完整媒体内容，只展示类型或已有文字说明。
- 文字快照是排查问题用的参考，并不保证与模型最终收到的内容完全相同；AstrBot 和其他插件之后还可能继续整理资料。
- 查看、预览和复制页面内容不会调用模型或发送消息。运行总览的每 5 秒刷新需要手动勾选，只在页面可见且没有未保存修改时进行。

## 日志与排障

**先看 Pages 的“决策回放”，通常不用读懂英文日志。** 它会说明当前步骤、耗时、是否已经发送，以及最终结果。需要更详细的信息时，再查看 AstrBot 的日志；部分过程信息只在详细日志（Debug）中显示。相同提醒可能合并显示，避免刷屏。

### 主动聊天没有发出来时怎么看

先打开 **决策回放**，选择对应会话的一轮运行，点击 **刷新记录** 更新当前阶段和耗时，再看最终结果。回放详情不是自动刷新的；运行总览的自动刷新开关只作用于总览。

| 看到的情况 | 含义 |
|---|---|
| 等待会话锁／准备上下文 | 还在排队或准备材料，不能据此判断模型出了问题。 |
| 等待聊天模型返回，仍为“进行中” | 还没有得到最终结果；一次调用的耗时可能包含服务内部重试。 |
| 一次模型尝试未成功 | 是过程记录，后续仍可能通过重试或备用模型完成。 |
| 原生 Agent 最终失败 | 主框架已经返回最终失败结果，再结合最近的模型和工具记录定位。 |
| 任务超时 | 达到了你填写的插件额外总时限，不等同于单次模型请求超时；留空时不会触发这个插件总时限。 |
| 已发送，后续失败／超时 | 至少有一次发送已确认成功，之后的模型、工具或收尾步骤出了问题。 |
| 主动发送已放弃 | 睡眠、暂停日程或其他发送资格不再满足，原因会说明；不是模型失败。 |

记录中最近一次错误可能已经通过重试解决，**判断是否成功要看整轮最终状态**。页面显示的模型调用次数也不等于服务内部的实际请求次数，不能拿它直接计算费用。

### 配置错误与原因码

遇到设置错误，先按页面提示修正。一般只暂停受影响的功能或会话组；如果 SID 重复或公共设置有误，插件可能无法运行。日程已开启但内容有误时，也会暂停对应范围的主动功能，避免在本应安静的时候发言。管理员可以发送 `/active_status` 查看当前会话的设置问题和最近说明。

<details>
<summary>按日志里的英文原因码查问题（可选）</summary>

日志同时带有中文解释和英文原因码。如果需要对照英文代码，可查下面的列表：

- `ORIGINAL_ACTIVE_REPLY_ENABLED`：原版主动回复仍开启，插件智能插话已跳过。
- `GROUP_HISTORY_DISABLED` / `GROUP_HISTORY_READ_FAILED`：原生群历史未开启或读取失败，默认跳过。
- `CONTEXT_RUNTIME_FALLBACK`：用户选择了不完整的运行时摘要模式。
- `CONTEXT_PREPARED`：详细日志显示参考资料来自哪里、选了多少条。
- `CONFIG_INVALID`：按日志中的字段路径修正配置，受影响功能已暂停。
- `DECISION_COMPLETED`：记录三项原始分、权重、最终分、阈值和是否触发。
- `MODEL_TIMEOUT` / `MODEL_INVALID`：判断服务超时或返回格式不正确。
- `JUDGMENT_INPUT` / `INPUT_TOO_LARGE`：最终判断输入预算，或固定输入仍然过大。
- `JEV_HTTP` / `MODEL_ERROR`：判断服务拒绝请求或调用未成功；检查地址、密钥、服务余额和日志中的原因。
- `MODEL_RETRY`：临时故障后的有界重试，等待时间也计入总超时。
- `EMPTY_SESSION_GROUP`：空组可保存，但没有目标；仍然启用白名单模式。
- `IMAGE_CONTEXT_UNAVAILABLE`：当前框架不支持只读取得待注入图片转述，不影响已保存文字的读取。
- `AGENT_REQUESTED` / `AGENT_STARTED` / `AGENT_DONE`：原生 Agent 请求/开始/完成。
- `PROACTIVE_SCHEDULED`：主动聊天的下一次计划。
- `PROACTIVE_TIMEOUT`：达到用户填写的插件额外总时限；留空时不启用该限制，不等同于单次模型请求超时。
- `PROACTIVE_RUN_FAILED`：准备聊天资料、启动助手或保存结果等步骤出了问题；先看卡在哪一步，不直接等同于模型失败。
- `PROACTIVE_LLM_ATTEMPT_ERROR`：一次模型尝试未成功，主框架仍可能重试或切换备用模型；这不是整轮失败结论。
- `PROACTIVE_NATIVE_ERROR`：主框架已判定本轮 Agent 最终失败；插件据此记录失败，不通过猜测日志文字下结论。
- `PROACTIVE_TOOL_FAILED`：工具执行未成功，主框架可能继续处理；请结合最终结果判断。
- `PROACTIVE_SEND_SKIPPED`：因睡眠、暂停日程或其他发送限制放弃发送，具体原因在记录中说明；不等同于模型失败。
- `PROACTIVE_CLEANUP_PENDING`：任务要求停止后，某个工具仍没有结束。插件暂停主动功能以免重复执行；请检查该工具或重启 AstrBot，已经完成的操作不能撤销。
- `BARE_SID_AMBIGUOUS`：裸号码无法明确补全，请改用完整 SID。
- `PROACTIVE_RUNNER_UNSUPPORTED`：当前是第三方 Runner，未替换它运行。
- `MESSAGE_SENT`：原生消息/发送工具返回成功，不代表整轮任务已完成。

</details>

需要求助时，尽量提供 **同一次运行的回放结果和相关日志**。日志中的 `run_id` 就是本次运行的编号，用它可以把前后过程对应起来。不要只截取最后一句“失败”，也不要公开发送密钥或未经检查的私人聊天内容。

## 限制与已知事项

- 其他插件若用自己的方式发送消息，本插件可能无法完整统计，精力和冷却的计算也会受影响。
- 机器人保存的对话记录与群里的全部发言不一定相同；能参考多少内容，还取决于 AstrBot 的历史保存和长对话整理设置。
- 不同平台对“群号/用户号”和主动消息支持不同。完整 SID 是最可靠的配置方式。
