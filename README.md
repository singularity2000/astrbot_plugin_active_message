# 主动会话插件

AstrBot 插件 **主动会话插件**（`astrbot_plugin_active_message`）包含两个功能：

- **智能插话**：仅群聊。机器人不再单纯按概率随机回复，而是结合模型判断、群活跃情况、机器人精力计算分数，超过阈值才参与。
- **主动聊天**：机器人根据睡眠、正常、活跃三档作息状态和随机时间，在指定群聊或私聊中主动发起聊天。

此外，可独立开启 **日程意识**：让机器人知道当前及未来七天的安排，并按日程暂停插件自身的插话或主动聊天；不会创建或接管原生未来任务。

首次安装默认关闭。最上方的 **“启用主动会话插件”是总开关**：关闭后，所有会话的智能插话、主动聊天和日程意识都停止。会话组只覆盖对应的全局功能开关，不能覆盖总开关。建议先选一个测试会话，再开启插件。

## 不知道从哪里设置？

Pages（插件独立页面）和 AstrBot 原生插件配置页，修改的是**同一份配置**。Pages 按使用场景分页面，原生配置页按功能分组；共同配置项使用相同名称。建议一次只在一个页面编辑，避免两边互相覆盖。

| 我想做什么 | Pages 入口 | 原生配置页入口 |
|---|---|---|
| 只让机器人在指定群或私聊生效 | 会话组 | 会话组：选择生效范围 |
| 让机器人判断是否适合接话 | 智能插话 | 智能插话设置（仅群聊） |
| 让机器人隔一段时间主动找人聊 | 主动聊天 | 主动聊天设置（群聊和私聊） |
| 每天晚上不主动聊天、白天更活跃 | 作息与日程 → 作息管理 | 主动聊天设置 → 睡眠时间段／活跃时间段 |
| 让机器人知道午休、活动等安排 | 作息与日程 → 日程管理 | 日程管理 |
| 看机器人为什么没有说话 | 运行总览／决策回放 | 运行记录与排查（开启记录；详情在 Pages 查看） |

几个常见词：**会话**就是一个群聊或私聊；**SID** 是 AstrBot 用来区分会话的地址；**全局**是通用默认设置；**跟随全局**表示沿用默认值；**本组覆盖**表示只给这一组另设一个值；**Agent** 指 AstrBot 原来负责回复、调用工具的聊天助手。

> **作息不等于禁言，日程不等于提醒。** 睡眠时段只暂停主动聊天，不阻止智能插话或正常回复。想在某个日期或时段同时暂停两种主动功能，请在日程中勾选对应选项。想要准时提醒，请使用 AstrBot 原生未来任务。

## 重要提醒

1. 开启本插件前，请先关闭 AstrBot 自带的“主动回复”。检测到当前会话仍开启原版主动回复时，本插件跳过智能插话，并输出一次中文 Warning 提醒。
2. 插件会调用你选择的判断服务。LLM 模式使用 AstrBot 已配置的模型提供商；Jev 模式会将选定的原生历史、近期群消息和模板资料发送到配置的 Jev 接口（官方或中转站）。LLM 模式将同类资料发送给所选模型提供商；请确认数据外发范围。
3. 插件的主动聊天默认按普通成员身份运行，不冒充管理员。若目标平台或 AstrBot 版本无法可靠保证权限，主动任务会跳过并记录日志。
4. 智能插话会使用当前事件的原始发言者身份交给 AstrBot 原生 Agent。

## 快速开始

### 1. 先选功能，再检查框架设置

如果要用智能插话，请先在 AstrBot 设置中关闭自带的“主动回复”，避免两套功能冲突。仅使用主动聊天或日程意识时，不需要配置插话判断模型。

### 2. 配置判断模式（仅智能插话需要）

在插件配置的“判断模型”中二选一：

- **LLM**：选择一个 AstrBot 已配置的聊天模型，专门负责回答“现在是否适合插话”。
- **Jev**：填写对应服务的 API Key，默认官方地址为 `https://api.typesafe.ai/v1/systemone`、模型为 `jev-latest`。支持填写兼容 TypeSafe 协议的中转站完整 HTTPS 地址；不会自动拼接路径，也不会跟随重定向。URL 不携带用户名密码、查询参数或 `#` 片段，凭据只填写在 Key 栏。普通 OpenAI 聊天接口不能直接当作 Jev 接口使用。HTTP 只允许本机回环地址，便于本地调试。

判断模型只产生 0～1 的判断分，不直接生成最终聊天回复。判断超时默认 **30 秒**，包含等待重试的时间。临时限流、部分服务错误和连接故障默认最多额外重试 **1 次**，可设为 `0` 关闭；格式或鉴权错误不重试。失败时本轮不插话。LLM 与 Jev 的连接可同时配置，方便不同会话组分别选择模式；Key 会发送给你填写的服务，请只使用可信地址。已有配置中保存的超时值不会被默认值强行覆盖。

### 3. 确认聊天参考资料

“聊天参考资料”控制判断模型读取的资料和插件额外补充的聊天信息。刚上手通常保留默认值即可；这些限制不会删除聊天记录：

| 设置 | 默认 | 含义 |
|---|---:|---|
| 判断参考的对话历史条数 | `20` | 先读取当前分支最后 N 条已保存消息，再生成受预算约束的文字副本。`0` 表示先选全部；条数不是对话轮数。 |
| 补充的近期群消息条数 | `50` | 通过 AstrBot 原生消息历史接口读取最后 N 条群消息；`0` 表示全部已保留群记录。智能插话与主动聊天的原生 Agent 也会补入这些资料。 |
| 群消息历史不可用时 | `skip` | 跳过判断／主动聊天并提示原因；选择 `runtime` 才允许使用不完整的插件短期摘要。 |
| 判断输入长度上限（估算 token） | `12000` | 对最终渲染后的指令与输入做保守估算，不是服务端精确分词或计费值。 |
| 判断输入字数上限（字符） | `48000` | 与 token 预算同时生效；超出时先去掉较旧参考记录。 |
| 每条参考资料的字数上限（字符） | `4000` | 超长文字保留开头并标记缩减；固定判断指令仍超总预算时明确跳过，不偷偷改写指令。 |
| 使用已有的图片文字说明 | 开启 | 使用框架已经生成的图片说明，不额外识图，也不影响框架继续使用这些说明。 |

**群聊请先开启 AstrBot 的群消息历史保存**（主框架配置键 `provider_ltm_settings.group_message_history_enable`）。开启后只能积累此后的消息，不能补回从未保存的内容。普通群聊上下文感知与群消息历史保存是不同功能。

选定历史自动加入 LLM/Jev 判断输入，不必在模板里手写 `{conversation_history}`。私聊使用当前原生分支历史，不要求群历史开关。当前消息另行附加，避免漏掉正在触发判断的这一条。

“全部”仅指主框架仍保留的数据，且最终判断输入仍受预算限制。已压缩、删除或未保存的消息无法恢复。图片、音频等二进制编码不作为文字投喂；没有转述时仅保留 `[Image]` 等标签。群聊上下文感知和自动理解图片均开启且框架已有结果时，插件可读取待注入的图片转述；已经进入分支的转述也随文字历史读取。框架不支持该读取能力时会告警，不擅自重复识图。

**这些限制只作用于判断材料和插件补充资料，不改动原生历史。** 真正发言的 Agent 仍使用原生会话、人格、工具和框架的上下文管理。不同来源可能重叠；默认模板不再重复放入自动附加的历史，若自行多次引用历史占位符，最终预算也会计入这些重复内容。Jev 只支持文字；请根据官方模型与中转限制设置预算，不要把总请求的 64k 与 `state + 最长问题` 的 32k 限制混为一谈。

### 4. 配置会话

- 不添加会话组：对所有支持的会话生效；智能插话只处理群聊，主动聊天支持群聊和私聊。
- 添加一个或多个会话组：自动进入白名单模式，只处理组内 SID。
- 推荐填写完整 SID，例如：`平台实例ID:GroupMessage:群号` 或 `平台实例ID:FriendMessage:QQ号`。
- 只填数字群号/QQ 号时，插件会在收到明确平台事件后于后台补全。如果启用了多个平台适配器，请填写完整 SID；同一数字在群聊/私聊间出现歧义时，不会擅自猜测。
- 主动聊天的“全会话”模式只会针对插件已观察到或恢复的会话安排任务，不会枚举平台通讯录里的陌生会话。

### 5. 开启功能

确认配置正确后，先打开最上方“启用主动会话插件”总开关，再开启对应全局功能，或将测试会话组的对应功能设为“开启”。普通插件配置页保存后请确认已重载；使用本插件 Pages 的“保存并生效”无需另行重载。建议先只填写一个测试会话，而不是立刻对所有会话开启。

管理员可在当前会话使用 `/active_status`，查看完整 SID、生效范围、阈值、权重和下次主动尝试时间。将 SID 复制到“会话地址（SID）列表”，每项填一个。

如果智能插话日志显示“没有原生对话分支”，先在该会话正常与机器人聊一次，或使用 `/new`。不要为了让插件工作而更换 SID 或另建孤立的聊天链。

## 会话组与继承

一个会话组用名称说明用途，并配置多个 SID。组内会话只是共用设置，**历史、冷却、精力和每日轮次仍按 SID 分开**。

| 配置范围 | 会话组可覆盖的内容 |
|---|---|
| 智能插话 | 阈值、停顿等待、最长合并时间、判断结果有效期、三项权重、活跃／精力参数、发言提示词 |
| 判断模型 | 判断模式、判断提示词和判断补充信息模板；Provider、接口、Key、超时和重试继续使用全局值 |
| 主动聊天 | 随机间隔、每日上限、时区、睡眠／活跃时段、倍率、任务说明和提示词列表 |
| 日程意识 | 跟随全局／开启／关闭；共享全局日程、添加本组日程、排除指定全局日程 |
| 共享设置 | 上下文读取条数、文字／token 预算、图片转述复用、历史缺失策略，以及同时影响两项功能的共享冷却 |
| 仅全局 | 总开关、模型连接、运行时记录容量、并发额度、任务总超时、诊断容量与时限 |

- **留空跟随全局；`0` 是实际值。** 提示词列表为空也表示继承。
- 本组智能插话、主动聊天和日程意识分别选择 **跟随全局／开启／关闭**，默认跟随全局。
- **跟随全局**：采用全局“启用智能插话”或“启用主动聊天”的对应值。
- **开启**：本组开启该功能，可以覆盖对应的全局功能关闭设置；仍要满足范围、配置校验、框架权限及实际触发条件。
- **关闭**：本组不运行该功能。关闭不删除参数，页面仍可编辑。
- 列表为空是全局范围；添加任何组就进入白名单。空组允许保存，但没有目标并会产生警告。
- **三种选择都受最上方“启用主动会话插件”总开关控制**。总开关关闭后所有会话都停止；也不能越过 AstrBot 插件管理中的停用或卸载。
- 本组睡眠／活跃时段留空仍是继承；填写 **`无`** 才表示本组不设置该类时段。
- 同一个 SID 不能放进多个组；同组多个 SID 不会合并成一个聊天会话。

**例子：**全局阈值 `0.7`、共享冷却 `60` 秒。工作群只把阈值填写为 `0.9`，其他项留空，那么工作群使用 `0.9`，其他组仍使用 `0.7`；以后全局冷却改成 `120` 秒，这个工作群也跟随变成 `120` 秒。Pages 用“本组覆盖”徽标显示来源，并对比全局与实际值；“本组固定 · 当前与全局相同”仍是独立设置，以后不会随全局变化。可以一键恢复跟随全局，或只看本页覆盖项。

判断提示词和判断补充信息模板在 **智能插话 → 顶部选择会话组** 中配置，不在会话组管理卡片里。判断提示词决定“要不要开口”，发言提示词决定“准备开口时如何参与”。会话组卡片支持宽屏两列、窄屏单列，可拖动手柄或使用上移／下移；保存后顺序写入原生配置的会话组列表。

## 智能插话的分数

先把下面三项分别算成 0～1 的分数，再按你设置的权重合成总分。权重越大，通常越重视这一项：

| 评分项目 | 含义 |
|---|---|
| 模型判断 | 模型认为此时参与是否自然、有帮助。 |
| 群活跃情况 | 最近一段时间内其他账号的发言条数，以及最近一条消息距今多久。 |
| 机器人精力 | 近期机器人成功发送的消息越多，精力分越低。 |

默认权重：模型 `0.50`、群活跃 `0.25`、机器人精力 `0.25`，也就是重视程度为 2∶1∶1。权重不必加起来等于 1，插件会自动换算占比。

- 正权重：该项分数越高，最终分越高。
- 负权重：该项反向生效，先使用 `1 - 原始分`，再参与加权。
- `0`：该项不参与。
- 三个权重都为 `0`：智能插话配置无效，暂停插话；不因此关闭配置正确的主动聊天。
- 最终分必须严格大于阈值才触发。

### 权重如何合成

```text
某项有效分 = 原始分                  （权重为正）
某项有效分 = 1 - 原始分              （权重为负）
最终分 = Σ（|权重| × 有效分）÷ Σ|权重|
```

例如模型分 `0.8`、活跃分 `0.6`、精力分 `1`，默认权重得到 `0.8×0.5 + 0.6×0.25 + 1×0.25 = 0.8`，高于默认阈值 `0.7`，评分通过。如果活跃权重改为 `-0.25`，活跃有效分变成 `0.4`，最终分为 `0.75`，仍高于 `0.7`；若另将阈值设为 `0.75`，则**正好等于阈值，不触发**。权重 `2、1、1` 与 `0.5、0.25、0.25` 效果一样。

### 活跃分与精力分

```text
条数分 = min（近期消息数 ÷ 目标消息数，1）
新鲜度 = max（1 - 距最近消息秒数 ÷ 新鲜度衰减秒数，0）
活跃分 = 条数分 × 新鲜度

精力分 = max（1 - 近期机器人发送记录数 ÷ 目标发送数，0）
```

默认活跃窗口为 600 秒、目标 8 条、新鲜度衰减 300 秒。窗口内 4 条消息且最近一条距今 3 秒时，活跃分为 `(4÷8)×(1-3÷300)=0.495`。这里只区分机器人自身与其他发言账号，不识别其他账号是否为机器人。

默认精力窗口为 3600 秒、目标 5 次发送；0、1、2、3、4、5 次发送分别对应 `1、0.8、0.6、0.4、0.2、0`。这是按时间窗口统计，不是逐秒恢复的体力条。普通回复如果被原生发送钩子观测到，也会影响精力和共享冷却。

**精力分为 0 不等于禁止插话。** 在默认权重下，如果模型分和活跃分都为 1，最终分仍为 `0.75`，可以超过默认阈值 `0.7`。是否通过取决于当前权重、其他分数与阈值；Pages 的试算面板可用自选示例验证，不会调用模型或发送消息。统计按 SID 独立，不同会话不共享精力；主框架若按群成员隔离会话，同一个群也可能有多个统计对象。

统计记录同时受时间窗口和“每个会话的短期记录上限（条）”上限约束。该上限不是原生历史读取条数；后者在“聊天参考资料”里独立设置。

### 消息如何合并，判断何时作废

| 设置 | 默认 | 用途 |
|---|---:|---|
| 停顿等待 | 3 秒 | 大家停顿这么久后开始判断，避免每一条都调用模型。 |
| 最长合并时间 | 10 秒 | 从本批第一条消息开始计算；群里一直有人说话，也不会无限延后判断。 |
| 判断结果有效期 | 45 秒 | 从取得判断快照起计时，包含排队和调用时间；超过后丢弃旧结果。 |

例如消息在第 0、2、4、6、8 秒连续到达，插件最晚在约第 10 秒结束合并，而不是始终重新等待 3 秒。判断请求开始后，普通新消息只更新上下文，不再反复取消请求；真正发言前会刷新原生上下文，但仍保留触发事件的真实发送者身份。

因此**判断快照与发言上下文可能来自相邻的两个时刻**，运行检查台会分步骤记录。遇到正常 @／唤醒、会话分支切换、机器人已发言进入冷却、结果过期或插件停止时，旧判断不再激活 Agent。判断服务仍可能对已发出的取消请求计费，插件不能代服务商撤销费用。

## 自定义提示词和占位符

“判断提示词”和“智能插话发言提示词列表”是两套不同配置：

- 判断提示词：给 LLM/Jev，决定模型判断分。
- 发言提示词：可信的行为指令临时追加到原生 Agent 系统提示词，指导最终回复；聊天正文、昵称、历史和模型理由等外部占位符改为用户层参考资料，不提升为系统指令。

提示词列表每次随机选择一条，允许连续重复。主动聊天还可单独配置“任务说明”；只能发送至原 SID、必须通过发送工具等执行约束仍由程序保留。

模板只处理 `{变量名}`，不会执行代码或表达式。系统提示中的外部占位符会显示为对应参考资料字段的指引，实际值放在用户层 JSON 资料中。常用占位符：

| 占位符 | 用途 |
|---|---|
| `{persona_prompt}` | 当前会话人格提示词的文字副本，受单条参考字符预算限制。它不是完整系统提示词，原生 Agent 的人格、安全规则和工具说明仍由框架管理。 |
| `{persona_name}` | 当前人格名称。 |
| `{conversation_history}` | 按上下文配置选取、去媒体编码并受预算约束的分支历史文字副本。它不等于全部群闲聊，也不是未经处理的原生 JSON。 |
| `{current_message}` | 当前触发判断的消息文字，受单条预算限制。 |
| `{image_descriptions}` | 当前会话原生群上下文中已有的图片转述；未取得时为空列表，不自行编造。 |
| `{recent_messages}` | 按上下文设置读取的原生近期群消息；显式选择 runtime 降级时才是不完整的插件短期摘要。 |
| `{now}` `{current_time}` `{date}` `{weekday}` `{time}` | 当前时间、日期、星期和消息时间。 |
| `{platform}` `{platform_id}` `{message_type}` `{chat_type}` `{session_id}` `{sid}` | 平台、实例、群/私聊类型、会话编号和完整 SID。 |
| `{group_id}` `{sender_id}` `{sender_name}` `{user_id}` `{username}` | 群号、真实发言者 ID 和昵称；后两个是兼容别名。主动聊天没有原始发言人时为“不适用”。 |
| `{group_message_count}` `{silence_seconds}` | 活跃统计时长内其他账号的消息数、距最近一条消息的秒数。 |
| `{activity_score}` `{energy_score}` | 群活跃原始分、机器人精力原始分。 |
| `{model_score}` `{score}` `{threshold}` `{decision_reason}` | 模型分、最终分、阈值和理由；判断提示词中不要使用判断后才产生的 `{model_score}`、`{score}`、`{decision_reason}`；主动聊天中这些判断分字段为“不适用”。 |
| `{activity_level}` `{mood}` `{trigger_type}` | 群活跃档位（低/中/高）、作息状态（睡眠/正常/活跃）和触发类型（智能插话/主动聊天）。 |
| `{user_last_message_time}` `{user_last_message_time_ago}` `{ai_last_sent_time}` `{unreplied_count}` | 最近真人发言、距今时间、机器人最近发送时间和连续未获回复次数。 |
| `{user_context}` | 根据当前会话信息组成的概况。 |
| `{schedule_current}` | 本会话正在进行的日程；关闭日程或没有事项时为空列表。 |
| `{schedule_upcoming}` | 未来七天内每条日程的下一次安排，最多十二项；不是所有重复轮次的长清单。 |

日程资料也会自动补充给支持的原生 Agent；不写占位符仍可知情。以上占位符用于自定义模板，不提供 `{calendar_today}`。

## 主动聊天作息与调度

- **睡眠**：睡眠时间段内不发起新的主动聊天；只保留下次尝试时间，不会睡醒后补发一批积压消息。
- **正常**：使用配置的最短/最长随机间隔。
- **活跃**：将随机间隔乘以活跃倍率，通常更容易主动聊天。

每日主动聊天轮次上限由你在“主动聊天设置 → 每个会话每日主动聊天上限（轮）”中配置。一轮 Agent 即使分段或发多条消息也只计一次；至少有一次原生发送接口返回成功才计数，不代表用户已读。Agent 可以判断“不适合打扰”而不发送。插件按计划时间等待，到点后才尝试，不会不停扫描所有会话。如果已有任务占满运行名额，或该会话的聊天助手正忙，实际开始时间可能推迟。睡眠档仅控制主动聊天，不代替主框架对 @ 和正常问答的处理。

主动聊天会像 AstrBot 的“未来任务”一样唤醒原来的聊天助手，沿用原会话的对话分支、人格和允许使用的工具。任务按普通成员权限运行，不冒充管理员。目前需要使用 AstrBot 内置聊天助手（local）；不支持时会跳过，不会偷偷换掉你选择的第三方助手。

时间段支持逗号分隔多个区间，例如 `23:00-07:00,12:00-13:00`；支持跨午夜。起点包含、终点不包含；留空表示没有该类时间段；起止相同表示全天。睡眠与活跃重叠时睡眠优先。如果整个等待过程都处于活跃时段，默认间隔为 30～180 分钟乘以 0.6，即 18～108 分钟；睡眠期间安排的机会可能在睡眠结束时直接尝试。

“每日上限”限制成功主动发言的轮次，不限制失败或未发送的模型尝试次数。用户刚发言不会自动重置整段主动间隔；当前也不根据连续未回复次数自动增加等待时间。这里的“心情”占位符只表示作息状态，没有独立情绪分析；日程意识另行配置，不改变这个占位符的含义。

### 哪些设置不会相互影响

- “发言后等待时间（共享冷却，秒）”同时限制智能插话和主动聊天；正常 @ 回复不受它限制。
- 判断模型只打分；主动聊天不经过插话阈值。聊天内容仍由原生 Agent 产生。
- 会话组使用统一的生效配置解析：同一 SID 的运行逻辑、校验和 Pages 预览读取同一组结果，不维护第二套页面配置。
- “运行资源与超时”可设置判断／主动聊天并发数，以及一轮主动任务最长时间。权限、原 SID 发送范围、500 会话安全容量及响应大小保护不作为行为调节项。

## 日程意识

### 先试一条午休日程

1. 打开 **作息与日程**，顶部选择全局或一个测试会话组。
2. 打开“启用日程意识”，或把“本组日程意识”设为“开启”。插件总开关也需要开启；智能插话、主动聊天可以保持关闭。
3. 点击“添加全局日程”或“添加本组日程”，填写“午休”、开始日期，选择“时段”，填 `12:30` 到 `14:00`。
4. 选择“每周”，勾选周一到周五。想每天生效就选择“每天”。按需要勾选“期间暂停智能插话”和／或“期间暂停主动聊天”。
5. 点击“加入页面草稿”，在“日历预览”中点击日期检查结果，最后点击页面右上角 **保存并生效**。

**预期效果：**午休期间，勾选的插件主动功能暂停；正常 @、命令和框架原生未来任务不受影响。14:00 后恢复原有规则，但不会立刻补发消息。若两个暂停选项都不选，机器人只知道这条安排，不改变发言时机。

### 知道日程，不等于自动提醒

- **机器人日程**：角色安排，如阅读、休息。它不是“已经真实读完一本书”的证据。
- **会话事项**：这个群或私聊的活动、约定等。分组事项只提供给匹配的会话，不带入其他组。
- **准时提醒**：直接在聊天里请 Agent 使用 AstrBot 原生未来任务，例如“每天 12:25 提醒我准备午休”。本插件不创建、不接管、不拦截这些提醒，也不判断原生提醒是否打破安静时段。

日程意识和两个主动功能分别控制。可以只开启日程意识，让正常回复知道当前安排，不让插件主动搭话。日程背景通过原生 Agent 开始钩子添加为临时参考资料，不替换人格、历史和工具权限；在支持该接口的原生上下文保存流程中，临时内容不会原样堆进历史。旧框架没有临时内容接口时会提示并跳过注入，不强行改写历史。

### 全局和会话组如何配合

**会话组日历 = 全局日程 + 本组新增 − 本组排除。**全局日程标注“来自全局”，可以在本组排除或恢复继承；修改全局事项请切换到全局范围。排除不影响其他组。多个日程重叠时，只要其中一条要求暂停，该插件功能就暂停。

Pages 和原生配置页使用同一份配置。日程统一保存在“日程意识 → 日程事项”目录：`group_id` 留空表示全局，填写组的“日程分组标识”表示该组专属。Pages 添加本组事项时自动生成关联标识，无需手填；编辑日程时也可用“日程适用范围”选择全局或其他组。原生配置页可复制组标识到对应事项。日程自身也有固定标识 `id`，排除列表使用它而不是日程标题。

**Pages 日常操作只需选择组名，不展示内部的日程分组标识。**标识由插件自动维护，不是 SID。原生配置页保留该字段供手动关联；若在那里修改标识，需同时更新日程引用，陌生或冲突标识会报错，不会退回全局。删除会话组时，Pages 会确认并删除它的专属日程，不删除全局事项。

### 日期和重复方式

| 配置 | 含义 |
|---|---|
| 全天 | 从当天零点持续到次日零点；可以配合各类普通重复方式 |
| 时段 | 按开始／结束时间计算；结束早于开始表示次日结束，相同时间请改选全天 |
| 不重复 | 只在开始日期发生一次 |
| 每天 | 从开始日期起，每天生效 |
| 每周 | 周一至周日可多选，例如周一／三／五，或周六／日 |
| 每年 | 同月同日重复；2 月 29 日只在闰年出现，不擅自改成 2 月 28 日 |
| Cron | 五段表达式决定开始时间，“每次持续分钟”决定结束；只计算日程，不创建发送任务 |

每周一至周五只是固定星期，**没有中国法定节假日、调休或“中国工作日”功能，也没有相关依赖**。重复截止日期可留空，填写后包含当天开始的轮次；跨午夜事项不会在零点被截断。日期范围为 1900～2199 年。

Cron 顺序为 `分 时 日 月 周`，例如 `0 9 * * mon,wed,fri` 表示每周一／三／五 09:00 开始。星期数字采用周日 `0` 或 `7`、周一 `1` 的约定；日期和星期同时限制时需同时满足。持续时间为 1～1440 分钟。密集规则在某天多次出现时，日历按事项合并展示，详情列出前三次并注明还有更多；实际暂停判断不依赖展示条数。

日程使用“作息与日程”里的时区；留空则使用各会话的框架时区，再回退到系统时区。一个组的多个 SID 如果框架时区不同，页面使用首个 SID 预览，实际运行各自计算；需要统一时可显式填写 `Asia/Shanghai` 等时区。跨夏令时时，普通时间段不存在的起止时刻跳过该轮，重复的钟表时间只采用第一次。

日历按真实月份和星期排列，点击某天查看事项；可直接跳转月份，点击“今天”重新计算当前预览。状态标注本次预览时间，未保存时按草稿计算；切月份和分类不会改变配置。日程意识关闭时仍可预览，但不注入背景、不暂停行为。每个范围最多 100 条、总目录最多 1000 条；给 Agent 的当前和近日摘要各保留最多十二项，每项说明取前 160 字并标记缩减，暂停规则仍检查全部适用事项。

后续计划：提供可选的 AI 每日角色日程生成，生成结果可查看和修改；当前版本暂不支持。

## 运行检查台（Pages）

从 AstrBot 管理界面的插件页面入口打开本插件的 `console`／“主动会话 · 运行检查台”。直接打开 HTML 不会连接真实插件；页面与接口使用主框架的登录校验，不另起端口或服务。

| 子页 | 适合做什么 |
|---|---|
| 运行总览 | 查看总开关、会话范围、共享冷却、每日轮次、下一次计划和最近原因 |
| 决策回放 | 按会话选择一次运行，逐步检查收到消息、上下文、模型输入输出、算分、Agent 工具与发送记录 |
| 会话组 | 管理名称、SID、共享冷却、功能选择和排序；宽屏两列、窄屏单列 |
| 智能插话 | 调整判断模式、插话分数门槛、权重、停顿等待和精力，以及全局／分组的判断与发言提示词 |
| 主动聊天 | 调整间隔、每日轮次、任务说明和提示词 |
| 作息与日程 | 检查作息时间轴，管理全局／分组日程，在日历预览中查看安排和当前暂停原因 |
| 上下文与诊断 | 设置聊天参考资料、已有图片说明、临时文字快照和同时运行的任务上限 |

配置项、分区标题和日程弹窗旁的 **圆圈问号**可查看说明：鼠标悬停时持续显示，移到浮层内可以继续阅读和选中文字；点击问号可固定，再点问号、点外部或按 Esc 关闭。触屏直接点击即可；键盘用 Tab 聚焦问号也会显示。说明浮在页面上方，不会撑开表单。错误提示和运行状态仍直接显示。

在设置子页顶部选择“全局设置”或某个会话组。修改先保留为草稿，点击 **保存并生效** 才写入原生配置文件并应用：等待中的判断取消，主动计划重新安排，发送计数保留，旧诊断清空。若有 Agent 正在执行，页面会要求等待结束后再保存。检测到另一处已修改配置时，会拒绝覆盖，需重新载入。

“有未保存修改”右侧实时列出 **范围 → 页面 → 字段**，只显示修改位置，不展示提示词正文或密钥。以最近一次成功保存或重新载入的配置为基准：恢复某项原值，该位置立即消失；全部恢复后，标志消失且保存按钮禁用。列表单行横向排列，可横向滚动查看全部位置；提示区域保留固定高度，出现修改或增加条目时不会撑高顶部；主题、月份和页面切换不算配置改动。保存失败不会重置比较基准。

页面支持浅色、深色和自动主题；自动模式跟随主框架，缺少框架主题信息时跟随系统。桌面并排显示记录、步骤和详情，手机按单栏排列。标签页、主题与教程状态按 Dashboard 用户保存在框架 KV 中，不依赖 iframe 的浏览器存储，也不触发配置重载或重排计划。

左侧的 **新手引导** 可随时重新开始，支持下一步与跳过；只介绍操作，不会改配置或发送消息。字段旁的“说明”支持悬浮查看和点击展开。设置页顶部的编辑范围随滚动保持可见，避免把本组设置误当全局。

点击支持占位符的输入框，页面底部会出现 **临时占位符助手**：只显示当前输入框可用的标记和通俗说明，可搜索，点击即可插入原光标位置；选中文字时替换选区。点击其他区域、切换页面或按 Esc 收起。插入只修改草稿，仍需保存。原有 **占位符大全** 保留，用于浏览完整说明、示例和复制；判断前不能使用判断结果占位符。自动复制受浏览器限制时可从弹窗选择文字手动复制。

### 文字快照与隐私

**默认关闭文字快照采集。** 默认只保留步骤、时间、来源、条数、预算和分数；需要检查输入内容时，再开启“临时采集文字请求快照”。开启前的记录不会补采。快照始终隐藏媒体编码与已知凭据，并明确标记缩减；不能将它当作完整请求报文。

- 记录只暂存在插件进程内存；默认最多 **50 次运行、30 分钟、10 MiB**，达到任一限制就清理。每轮最多记录 100 个步骤，更长流程会明确显示省略数量。重载、保存配置或点击清空也会移除记录。
- 所有已登录 Dashboard、能够管理插件的使用者都可能看到这些资料。共享管理环境应谨慎开启。
- 不记录 HTTP 鉴权头；配置中的 Key 在页面读取时用占位符代替，诊断会隐藏已知凭据。聊天或工具结果本身仍可能包含其他隐私，不能把自动隐藏当作完整的隐私检测。
- 单步文字默认最多 **16000 字符**，可调整；更长的数据展示带有明确标记的文字预览。回放先加载步骤目录，再按需读取当前步骤正文，不一次传输整轮大记录。
- 群媒体仅展示标签或框架已有转述；非纯文本工具结果只记录可取得的文本部分，不保存二进制全文。
- **插件请求钩子快照不是最终网络报文。** 框架压缩和其他插件仍可能继续修改请求。判断模型的调用参数／Jev 请求体会单独记录；未捕获的阶段不会推测补齐。
- 查看、预览设置和复制 JSON 不会调用模型或发送消息。运行总览的 5 秒刷新需要手动勾选，只在页面可见、没有未保存修改时进行，与后台单闹钟调度无关。

## 日志与排障

日志包含中文解释和稳定原因码。原版冲突等提醒按原因和会话去重；冷却、模型故障等重复日志每个会话每 60 秒最多输出一次，并汇总省略次数。正常冷却、未过阈值、提示词注入、排期等细节使用 Debug；成功发送及生命周期保留 Info，异常保留 Warning/Error。Debug 与回放可查看输入字符／字节数、估算 token、缩减条数、排队耗时、重试次数及安全的 HTTP 状态码，不输出聊天正文。

配置按功能校验：关闭的功能不因其提示词／作息错误拖累另一个功能；日程字段始终校验，启用的日程配置无效时暂停本范围的插件主动功能，避免漏过禁止打扰规则；错误日志标明配置字段和修正方式。某个会话组的功能参数错误只暂停该组受影响功能；SID 冲突或公共结构错误会拒绝运行。管理员用 `/active_status` 查看配置错误和最近说明。常见原因码：

- `ORIGINAL_ACTIVE_REPLY_ENABLED`：原版主动回复仍开启，插件智能插话已跳过。
- `GROUP_HISTORY_DISABLED` / `GROUP_HISTORY_READ_FAILED`：原生群历史未开启或读取失败，默认跳过。
- `CONTEXT_RUNTIME_FALLBACK`：用户选择了不完整的运行时摘要模式。
- `CONTEXT_PREPARED`：Debug 展示两类上下文的来源与选取条数。
- `CONFIG_INVALID`：按日志中的字段路径修正配置，受影响功能已暂停。
- `DECISION_COMPLETED`：记录三项原始分、权重、最终分、阈值和是否触发。
- `MODEL_TIMEOUT` / `MODEL_INVALID`：判断服务超时或返回格式不正确。
- `JUDGMENT_INPUT` / `INPUT_TOO_LARGE`：最终判断输入预算，或固定输入仍然过大。
- `JEV_HTTP` / `MODEL_ERROR`：接口拒绝或调用失败；查看安全的 HTTP 状态码和异常类型，不凭笼统错误猜测原因。
- `MODEL_RETRY`：临时故障后的有界重试，等待时间也计入总超时。
- `EMPTY_SESSION_GROUP`：空组可保存，但没有目标；仍然启用白名单模式。
- `IMAGE_CONTEXT_UNAVAILABLE`：当前框架不支持只读取得待注入图片转述，不影响已保存文字的读取。
- `AGENT_REQUESTED` / `AGENT_STARTED` / `AGENT_DONE`：原生 Agent 请求/开始/完成。
- `PROACTIVE_SCHEDULED`：主动聊天的下一次计划。
- `BARE_SID_AMBIGUOUS`：裸号码无法明确补全，请改用完整 SID。
- `PROACTIVE_RUNNER_UNSUPPORTED`：当前是第三方 Runner，未替换它运行。
- `MESSAGE_SENT`：原生消息/发送工具返回成功。

本插件自己的日志不会输出 API Key、Authorization 请求头、完整人格提示词或完整聊天正文。若要排查问题，请提供同一 `run_id` 的 Info 和 Debug 日志。

## 限制与已知事项

- 机器人精力统计覆盖可通过原生消息/工具钩子观察到的发送轮次；直接绕过这些钩子的第三方插件发送不能保证被完整计入。
- AstrBot 的“对话分支历史”、群聊消息历史和群上下文感知不是同一份数据；模型能看到的范围受 AstrBot 自身配置和上下文压缩影响。
- 不同平台对“群号/用户号”和主动消息支持不同。完整 SID 是最可靠的配置方式。
