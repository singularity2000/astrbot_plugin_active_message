# 主动会话插件

AstrBot 插件 **主动会话插件**（`astrbot_plugin_active_message`）包含两个功能：

- **智能插话**：仅群聊。机器人不再单纯按概率随机回复，而是结合模型判断、群活跃情况、机器人精力计算分数，超过阈值才参与。
- **主动聊天**：机器人根据睡眠、正常、活跃三档作息状态和随机时间，在指定群聊或私聊中主动发起聊天。

首次安装默认关闭。建议先选一个测试会话，完成以下配置，再打开总开关。

[快速开始](#快速开始) · [会话组与继承](#会话组与继承) · [插话评分](#智能插话的分数) · [运行检查台](#运行检查台pages) · [排障](#日志与排障)

## 重要提醒

1. 开启本插件前，请先关闭 AstrBot 自带的“主动回复”。检测到当前会话仍开启原版主动回复时，本插件跳过智能插话，并输出一次中文 Warning 提醒。
2. 插件会调用你选择的判断服务。LLM 模式使用 AstrBot 已有 Provider；Jev 模式会将选定的原生历史、近期群消息和模板资料发送到配置的 Jev 接口（官方或中转站）。LLM 模式将同类资料发送给所选 Provider；请确认数据外发范围。
3. 插件的主动聊天默认按普通成员身份运行，不冒充管理员。若目标平台或 AstrBot 版本无法可靠保证权限，主动任务会跳过并记录日志。
4. 智能插话会使用当前事件的原始发言者身份交给 AstrBot 原生 Agent。

## 快速开始

### 1. 关闭原版主动回复

在 AstrBot 设置中关闭原版“主动回复”。

### 2. 配置判断模式

在插件配置的“判断模型”中二选一：

- **LLM**：选择一个 AstrBot 已有的聊天模型 Provider，专门负责回答“现在是否适合插话”。
- **Jev**：填写对应服务的 API Key，默认官方地址为 `https://api.typesafe.ai/v1/systemone`、模型为 `jev-latest`。支持填写兼容 TypeSafe 协议的中转站完整 HTTPS 地址；不会自动拼接路径，也不会跟随重定向。URL 不携带用户名密码、查询参数或 `#` 片段，凭据只填写在 Key 栏。普通 OpenAI 聊天接口不能直接当作 Jev 接口使用。HTTP 只允许本机回环地址，便于本地调试。

判断模型只产生 0～1 的判断分，不直接生成最终聊天回复。判断超时默认 **30 秒**，失败时本轮不插话。LLM 与 Jev 的连接可同时配置，方便不同会话组分别选择模式；Key 会发送给你填写的服务，请只使用可信地址。已有配置中保存的超时值不会被默认值强行覆盖。

### 3. 确认上下文范围

“上下文输入”控制判断模型看到的资料：

| 设置 | 默认 | 含义 |
|---|---:|---|
| 分支历史条数 | `0` | 读取当前分支全部已保存 JSON 消息；正整数只选最后 N 条。条数不是对话轮数。 |
| 近期群消息条数 | `50` | 通过 AstrBot 原生消息历史接口读取最后 N 条群消息；`0` 表示全部已保留群记录。智能插话与主动聊天的原生 Agent 也会补入这些资料。 |
| 群历史不可用策略 | `skip` | 跳过判断／主动聊天并提示原因；选择 `runtime` 才允许使用不完整的插件短期摘要。 |

**群聊请先开启 AstrBot 的群消息历史保存**（主框架配置键 `provider_ltm_settings.group_message_history_enable`）。开启后只能积累此后的消息，不能补回从未保存的内容。普通群聊上下文感知与群消息历史保存是不同功能。

选定历史自动加入 LLM/Jev 判断输入，不必在模板里手写 `{conversation_history}`。私聊使用当前原生分支历史，不要求群历史开关。当前消息另行附加，避免漏掉正在触发判断的这一条。

“全部”仅指主框架仍保留的数据：已压缩、删除或未保存的消息无法恢复；群图片、音频等为主框架保存的媒体标记，不等于识图或听音结果。原生分支与近期群历史可能重叠，输入会区分来源。若模型输入过长，请主动设置条数，插件不会悄悄截成固定字符数。

### 4. 配置会话

- 不添加会话组：对所有支持的会话生效；智能插话只处理群聊，主动聊天支持群聊和私聊。
- 添加一个或多个会话组：自动进入白名单模式，只处理组内 SID。
- 推荐填写完整 SID，例如：`平台实例ID:GroupMessage:群号` 或 `平台实例ID:FriendMessage:QQ号`。
- 只填数字群号/QQ 号时，插件会在收到明确平台事件后于后台补全。如果启用了多个平台适配器，请填写完整 SID；同一数字在群聊/私聊间出现歧义时，不会擅自猜测。
- 主动聊天的“全会话”模式只会针对插件已观察到或恢复的会话安排任务，不会枚举平台通讯录里的陌生会话。

### 5. 开启功能

确认配置正确后，再打开总开关及相应功能开关。普通插件配置页保存后请确认已重载；使用本插件 Pages 的“保存并生效”无需另行重载。建议先只填写一个测试会话，而不是立刻对所有会话开启。

管理员可在当前会话使用 `/active_status`，查看完整 SID、生效范围、阈值、权重和下次主动尝试时间。

如果智能插话日志显示“没有原生对话分支”，先在该会话正常与机器人聊一次，或使用 `/new`。不要为了让插件工作而更换 SID 或另建孤立的聊天链。

## 会话组与继承

一个会话组用名称说明用途，并配置多个 SID。组内会话只是共用设置，**历史、冷却、精力和每日轮次仍按 SID 分开**。

| 配置范围 | 会话组可覆盖的内容 |
|---|---|
| 智能插话 | 阈值、停顿等待、最长合并时间、判断结果有效时间、三项权重、活跃／精力参数、激活提示词 |
| 判断模型 | 只有“跟随全局 / llm / jev”下拉菜单；Provider、接口、Key、判断提示词与判断超时继续使用全局值 |
| 主动聊天 | 随机间隔、每日上限、时区、睡眠／活跃时段、倍率、任务说明和提示词列表 |
| 共享设置 | 上下文读取条数、历史缺失策略，以及同时影响两项功能的共享冷却 |
| 仅全局 | 总开关、模型连接、运行时记录容量、并发额度、任务总超时、诊断容量与时限 |

- **留空跟随全局；`0` 是实际值。** 提示词列表为空也表示继承。
- 关闭“本组启用智能插话／主动聊天”会折叠对应详细设置，不删除覆盖值；重新开启后仍可继续使用。
- 本组开关不能打开被全局关闭的功能。列表为空是全局范围；有组但组内 SID 为空则没有目标。
- 本组睡眠／活跃时段留空仍是继承；填写 **`无`** 才表示本组不设置该类时段。
- 同一个 SID 不能放进多个组；同组多个 SID 不会合并成一个聊天会话。

**例子：**全局阈值 `0.75`、共享冷却 `60` 秒。工作群只把阈值填写为 `0.9`，其他项留空，那么工作群使用 `0.9`，其他组仍使用 `0.75`；以后全局冷却改成 `120` 秒，这个工作群也跟随变成 `120` 秒。Pages 会显示详细覆盖项的实际值和来源，方便核对。

## 智能插话的分数

三个因子都先计算成 0～1 的原始分：

| 因子 | 含义 |
|---|---|
| 模型判断 | 模型认为此时参与是否自然、有帮助。 |
| 群活跃情况 | 最近一段时间的真人发言条数，以及最近一条消息距今多久。 |
| 机器人精力 | 近期机器人成功发送的消息越多，精力分越低。 |

默认权重：模型 `0.50`、群活跃 `0.25`、机器人精力 `0.25`。权重会按绝对值归一化。

- 正权重：该项分数越高，最终分越高。
- 负权重：该项反向生效，先使用 `1 - 原始分`，再参与加权。
- `0`：该项不参与。
- 三个权重都为 `0`：智能插话配置无效，暂停插话；不因此关闭配置正确的主动聊天。
- 最终分必须严格大于阈值才触发。

### 权重如何合成

```text
某项有效分 = 原始分                  （权重为正）
某项有效分 = 1 - 原始分              （权重为负）
最终分 = Σ（|权重| × 有效分）÷ Σ|权重|
```

例如模型分 `0.8`、活跃分 `0.6`、精力分 `1`，默认权重得到 `0.8×0.5 + 0.6×0.25 + 1×0.25 = 0.8`，高于默认阈值 `0.75`，触发插话。如果活跃权重改为 `-0.25`，活跃有效分变成 `0.4`，最终分为 `0.75`，**正好等于阈值，不触发**。权重 `2、1、1` 与 `0.5、0.25、0.25` 效果一样。

### 活跃分与精力分

```text
条数分 = min（近期消息数 ÷ 目标消息数，1）
新鲜度 = max（1 - 距最近消息秒数 ÷ 新鲜度衰减秒数，0）
活跃分 = 条数分 × 新鲜度

精力分 = max（1 - 近期机器人发送记录数 ÷ 目标发送数，0）
```

默认活跃窗口为 600 秒、目标 8 条、新鲜度衰减 300 秒。窗口内 4 条消息且最近一条距今 3 秒时，活跃分为 `(4÷8)×(1-3÷300)=0.495`。这里只区分机器人自身与其他发言账号，不识别其他账号是否为机器人。

默认精力窗口为 3600 秒、目标 3 次发送；0、1、2、3 次发送分别对应 `1、约0.667、约0.333、0`。这是按时间窗口统计，不是逐秒恢复的体力条。普通回复如果被原生发送钩子观测到，也会影响精力和共享冷却。

**默认精力耗尽后，即便模型分和活跃分都为 1，最终分也只有 0.75，无法严格超过阈值。** 这是默认规则的限制效果。统计按 SID 独立，不同会话不共享精力；主框架若按群成员隔离会话，同一个群也可能有多个统计对象。

统计记录同时受时间窗口和“运行时消息记录数”上限约束。该上限不是原生历史读取条数；后者在“上下文输入”里独立设置。

### 消息如何合并，判断何时作废

| 设置 | 默认 | 用途 |
|---|---:|---|
| 停顿等待 | 3 秒 | 大家停顿这么久后开始判断，避免每一条都调用模型。 |
| 最长合并时间 | 10 秒 | 从本批第一条消息开始计算；群里一直有人说话，也不会无限延后判断。 |
| 判断结果最大年龄 | 45 秒 | 从取得判断快照起计时，包含排队和调用时间；超过后丢弃旧结果。 |

例如消息在第 0、2、4、6、8 秒连续到达，插件最晚在约第 10 秒结束合并，而不是始终重新等待 3 秒。判断请求开始后，普通新消息只更新上下文，不再反复取消请求；真正发言前会刷新原生上下文，但仍保留触发事件的真实发送者身份。

因此**判断快照与发言上下文可能来自相邻的两个时刻**，运行检查台会分步骤记录。遇到正常 @／唤醒、会话分支切换、机器人已发言进入冷却、结果过期或插件停止时，旧判断不再激活 Agent。判断服务仍可能对已发出的取消请求计费，插件不能代服务商撤销费用。

## 自定义提示词和占位符

“判断提示词”和“激活提示词”是两套不同配置：

- 判断提示词：给 LLM/Jev，决定模型判断分。
- 激活提示词：可信的行为指令临时追加到原生 Agent 系统提示词，指导最终回复；聊天正文、昵称、历史和模型理由等外部占位符改为用户层参考资料，不提升为系统指令。

提示词列表每次随机选择一条，允许连续重复。主动聊天还可单独配置“任务说明”；只能发送至原 SID、必须通过发送工具等执行约束仍由程序保留。

模板只处理 `{变量名}`，不会执行代码或表达式。系统提示中的外部占位符会显示为对应参考资料字段的指引，实际值放在用户层 JSON 资料中。常用占位符：

| 占位符 | 用途 |
|---|---|
| `{persona_prompt}` | 当前会话实际生效的人格提示词全文。它不是完整系统提示词，安全规则和工具说明仍由 AstrBot 原生流程管理。 |
| `{persona_name}` | 当前人格名称。 |
| `{conversation_history}` | 按“上下文输入”选取的当前 AstrBot 分支 JSON 历史。它不等于全部群闲聊。 |
| `{current_message}` | 当前触发判断的消息。 |
| `{recent_messages}` | 按上下文设置读取的原生近期群消息；显式选择 runtime 降级时才是不完整的插件短期摘要。 |
| `{now}` `{current_time}` `{date}` `{weekday}` `{time}` | 当前时间、日期、星期和消息时间。 |
| `{platform}` `{platform_id}` `{message_type}` `{chat_type}` `{session_id}` `{sid}` | 平台、实例、群/私聊类型、会话编号和完整 SID。 |
| `{group_id}` `{sender_id}` `{sender_name}` `{user_id}` `{username}` | 群号、真实发言者 ID 和昵称；后两个是兼容别名。主动聊天没有原始发言人时为“不适用”。 |
| `{group_message_count}` `{silence_seconds}` | 活跃窗口内真人消息数、距离最近真人消息秒数。 |
| `{activity_score}` `{energy_score}` | 群活跃原始分、机器人精力原始分。 |
| `{model_score}` `{score}` `{threshold}` `{decision_reason}` | 模型分、最终分、阈值和理由；判断提示词中不要使用判断后才产生的 `{model_score}`、`{score}`、`{decision_reason}`；主动聊天中这些判断分字段为“不适用”。 |
| `{activity_level}` `{mood}` `{trigger_type}` | 群活跃档位（低/中/高）、作息状态（睡眠/正常/活跃）和触发类型（智能插话/主动聊天）。 |
| `{user_last_message_time}` `{user_last_message_time_ago}` `{ai_last_sent_time}` `{unreplied_count}` | 最近真人发言、距今时间、机器人最近发送时间和连续未获回复次数。 |
| `{user_context}` | 根据当前会话信息组成的概况。 |

这些命名参考了“心念”插件，但本插件不读取心念插件内部数据；没有实现本插件日历，因此不提供 `{calendar_today}`。

## 主动聊天作息与调度

- **睡眠**：睡眠时间段内不发起新的主动聊天；只保留下次尝试时间，不会睡醒后补发一批积压消息。
- **正常**：使用配置的最短/最长随机间隔。
- **活跃**：将随机间隔乘以活跃倍率，通常更容易主动聊天。

每日主动聊天轮次上限由你在“主动聊天设置 → 每个会话每日主动聊天轮次上限”中配置。一轮 Agent 即使分段或发多条消息也只计一次；至少有一次原生发送接口返回成功才计数，不代表用户已读。Agent 可以判断“不适合打扰”而不发送。调度器只等待所有会话中最近的计划时间；发现新目标或一轮任务结束后重新设闹钟，没有待执行目标时不定期扫描。实际开始仍受事件循环、并发额度和原生会话锁影响。睡眠档仅控制主动聊天，不代替主框架对 @ 和正常问答的处理。

主动聊天使用单闹钟安排时间，并复用 Future Task 使用的 `build_main_agent` 构建器。它能看到原会话分支、人格和当前允许的工具，且作为机器人自动任务以普通成员身份执行；不使用“管理员用户消息”冒充触发。当前只支持 AstrBot 内置（local）主 Agent，第三方 Agent Runner 不会被擅自替换。

时间段支持逗号分隔多个区间，例如 `23:00-07:00,12:00-13:00`；支持跨午夜。起点包含、终点不包含；留空表示没有该类时间段；起止相同表示全天。睡眠与活跃重叠时睡眠优先。活跃档默认把 30～180 分钟乘以 0.6，实际为 18～108 分钟；睡眠期间安排的机会可能在睡眠结束时直接尝试。

“每日上限”限制成功主动发言的轮次，不限制失败或未发送的模型尝试次数。用户刚发言不会自动重置整段主动间隔；当前也不根据连续未回复次数自动增加等待时间。这里的“心情”占位符只表示作息状态，没有独立情绪或日历系统。

### 配置边界

- “机器人插话冷却”实际上是当前会话的共享冷却，主动聊天也遵守；正常 @ 回复不受它限制。
- 判断模型只打分；主动聊天不经过插话阈值。聊天内容仍由原生 Agent 产生。
- 会话组使用统一的生效配置解析：同一 SID 的运行逻辑、校验和 Pages 预览读取同一组结果，不维护第二套页面配置。
- “运行资源与超时”可设置判断／主动聊天并发数，以及一轮主动任务最长时间。权限、原 SID 发送范围、500 会话安全容量及响应大小保护不作为行为调节项。

## 运行检查台（Pages）

从 AstrBot Dashboard 的插件页面入口打开本插件的 `console`／“主动会话 · 运行检查台”。直接打开 HTML 不会连接真实插件；页面与接口使用主框架的登录校验，不另起端口或服务。

| 子页 | 适合做什么 |
|---|---|
| 运行总览 | 查看总开关、会话范围、共享冷却、每日轮次、下一次计划和最近原因 |
| 决策回放 | 按会话选择一次运行，逐步检查收到消息、上下文、模型输入输出、算分、Agent 工具与发送记录 |
| 会话组 | 管理组名称、SID、共享冷却和功能开关 |
| 智能插话 | 调整判断模式、阈值、权重、防抖、精力和激活提示词 |
| 主动聊天 | 调整间隔、每日轮次、任务说明和提示词 |
| 作息与时间 | 用一天的时间轴检查睡眠／活跃区间和实际间隔；这里不是独立日历系统 |
| 上下文与诊断 | 控制历史读取、原文采集、保留期限、容量和全局运行资源 |

在设置子页顶部选择“全局设置”或某个会话组。修改先保留为草稿，点击 **保存并生效** 才写入原生配置文件并应用：等待中的判断取消，主动计划重新安排，发送计数保留，旧诊断清空。若有 Agent 正在执行，页面会要求等待结束后再保存。检测到另一处已修改配置时，会拒绝覆盖，需重新载入。

页面支持浅色、深色和自动主题；自动模式跟随主框架，缺少框架主题信息时跟随系统。桌面并排显示记录、步骤和详情，手机按单栏排列。即使浏览器禁止页面存储，手动主题在当前页面仍然有效。

### 原始数据与隐私

**默认关闭原文采集。** 默认只保留步骤、时间、来源、条数与分数；需要检查模型究竟收到了什么时，再开启“临时保留原始上下文”。开启前产生的记录不会被补回原文。

- 记录只暂存在插件进程内存；默认最多 **50 次运行、30 分钟、10 MiB**，达到任一限制就清理。每轮最多记录 100 个步骤，更长流程会明确显示省略数量。重载、保存配置或点击清空也会移除记录。
- 所有已登录 Dashboard、能够管理插件的使用者都可能看到这些资料。共享管理环境应谨慎开启。
- 不记录 HTTP 鉴权头；配置中的 Key 在页面读取时用占位符代替，诊断会隐藏已知凭据。聊天或工具结果本身仍可能包含其他隐私，不能把自动隐藏当作完整的隐私检测。
- 单步数据太大时明确标记“未保留全文”，不会悄悄截断后冒充完整输入。
- 群媒体是框架保存的标记；非纯文本工具结果只记录可取得的文本部分，不声称保存二进制全文。
- **插件请求钩子快照不是最终网络报文。** 框架压缩和其他插件仍可能继续修改请求。判断模型的调用参数／Jev 请求体会单独记录；未捕获的阶段不会推测补齐。
- 查看、预览设置和复制 JSON 不会调用模型或发送消息。运行总览的 5 秒刷新需要手动勾选，只在页面可见、没有未保存修改时进行，与后台单闹钟调度无关。

## 日志与排障

日志包含中文解释和稳定原因码。原版冲突等提醒按原因和会话去重；冷却、模型故障等重复日志每个会话每 60 秒最多输出一次，并汇总省略次数。Debug 可查看上下文来源、当前可用条数及实际选取条数，不输出正文。

配置按功能校验：关闭的功能不因其提示词／作息错误拖累另一个功能；错误日志标明配置字段和修正方式。某个会话组的功能参数错误只暂停该组受影响功能；SID 冲突或公共结构错误会拒绝运行。管理员用 `/active_status` 查看配置错误和最近说明。常见原因码：

- `ORIGINAL_ACTIVE_REPLY_ENABLED`：原版主动回复仍开启，插件智能插话已跳过。
- `GROUP_HISTORY_DISABLED` / `GROUP_HISTORY_READ_FAILED`：原生群历史未开启或读取失败，默认跳过。
- `CONTEXT_RUNTIME_FALLBACK`：用户选择了不完整的运行时摘要模式。
- `CONTEXT_PREPARED`：Debug 展示两类上下文的来源与选取条数。
- `CONFIG_INVALID`：按日志中的字段路径修正配置，受影响功能已暂停。
- `DECISION_COMPLETED`：记录三项原始分、权重、最终分、阈值和是否触发。
- `MODEL_TIMEOUT` / `MODEL_INVALID`：判断服务超时或返回格式不正确。
- `AGENT_REQUESTED` / `AGENT_STARTED` / `AGENT_DONE`：原生 Agent 请求/开始/完成。
- `PROACTIVE_SCHEDULED`：主动聊天的下一次计划。
- `BARE_SID_AMBIGUOUS`：裸号码无法明确补全，请改用完整 SID。
- `PROACTIVE_RUNNER_UNSUPPORTED`：当前是第三方 Runner，未替换它运行。
- `MESSAGE_SENT`：原生消息/发送工具返回成功。

本插件自己的日志不会输出 API Key、Authorization 请求头、完整人格提示词或完整聊天正文。若要排查问题，请提供同一 `run_id` 的 Info 和 Debug 日志。

## 限制与已知事项

- 机器人精力统计覆盖可通过原生消息/工具钩子观察到的发送轮次；直接绕过这些钩子的第三方插件发送不能保证被完整计入。
- 不设强制 AstrBot 版本范围，但依赖原生人格解析、主 Agent、消息历史和 Pages 接口；缺少接口的版本不能保证兼容。
- AstrBot 的“对话分支历史”、群聊消息历史和群上下文感知不是同一份数据；模型能看到的范围受 AstrBot 自身配置和上下文压缩影响。
- 不同平台对“群号/用户号”和主动消息支持不同。完整 SID 是最可靠的配置方式。
